## 4. 五条纪律（改代码时别破坏）

1. **禁止随机切分域**：域按中心/序列切。`prepare.py` 里源域内部按病例随机切 train/val 是允许的（那不是域划分），域之间绝不能混。
2. **目标域不参与调参**：超参在源域验证集上定死。
3. **每格至少 3 个种子**，报 mean ± std。
4. **一次只改一个变量**。
5. **判据先定，再跑**。

## 5.1 【重要】2026-09-29 全表归零事故

**现象**：`results.csv` 12 格全部 ~0.0001，`source_val_dice` 只有 0.000466。

**根因**：改成 GPU 增广时把顺序写反了。

```python
# 错误写法
xi = Xt[bi].float().div_(255.0).sub_(0.5).div_(0.25)   # 先归一化到 [-2, 2]
xi, yi = _augment_gpu(xi, yi)                            # 再增广
# 而 _augment_gpu 最后一行是 return x.clamp_(0, 1) —— 把负数全砍成 0
```

归一化后值域是 [-2, 2]，`clamp(0, 1)` 会把**负的一半全部抹平**，
软组织全黑。模型在被破坏的图上把 loss 降到 0.22，评估时输入是正确
归一化的图，两边分布对不上，于是什么都预测不出来。

**正确顺序**：先在 [0,1] 空间增广，最后才归一化。

```python
xi = Xt[bi].float().div_(255.0)     # [0,1]
xi, yi = _augment_gpu(xi, yi)       # 在这个空间 clamp(0,1) 是对的
xi = xi.sub_(0.5).div_(0.25)        # 最后归一化
```

**修复后验证**：同配置跑 20 epoch，源域 val Dice = **0.3602**（坏掉时 0.0005）。

**以后怎么防**：改完训练管线，先跑这个 4 秒的检查再开长训练。

```powershell
.\.venv\Scripts\python.exe 实验DG\code\_checksanity.py
```

它比较训练路径与评估路径喂给模型的张量分布，两边 mean 差超过 0.3 就报警。

**踩坑后必须清场**：`run_grid.py` 会跳过 `results.csv` 里已有的格子，
源模型权重也会按架构指纹复用。所以出问题后**必须先把 `results.csv` 改名、
把坏权重删掉**，否则坏结果会被当成"已完成"跳过。这次已处理，
坏结果留档在 `_invalid_20260929_results.csv`。

## 6. 模型质量的现状（重要，先读这一节）

### 已经试过的四组配置

| 配置 | epoch | batch | 源域 val Dice | T1W→OOP 零样本 |
|---|---|---|---|---|
| 2D UNet，1.6M 参数 | 80 | 8 | 0.433 | 0.094 |
| 2D UNet，6.5M 参数 | 100 | 16 | 0.408 | 0.054 |
| 2D + 强增广 | 100 | 32 | 0.420 | 0.100 |
| **2.5D（相邻三层）+ 强增广** | 60 | 32 | 0.416 | 0.102 |

**四组全卡在 0.41~0.43。** 这说明瓶颈不是容量、不是增广、也不是 2D/2.5D——
加参数反而略降（0.433→0.408），加增广没有用。

### 已经排除的

- **数据没问题**：把缓存切片和标签叠图看过，红色轮廓准确落在胰腺上，
  T1 与 OOP 的对比度差异也和论文描述一致。不是对齐或预处理 bug。
- **不是欠拟合**：训练病例 Dice 0.79，验证 0.42，中间是泛化差距。

### 还没排除的（按可能性排序）

1. **训练太短**。nnU-Net 标准配方是 ~1000 epoch，我们只跑了 60~100，
   而且 loss 一直在降。当前 `SOURCE_EPOCHS=300` 就是冲这个去的。
2. **验证集划分病态**。val 27 例里 17 例是 MCF，而 MCF 的 val Dice 只有 0.29
   （MCF 训练病例 0.74）。随机切分可能把 MCF 里某个特殊子协议整块切进了 val。
   用 `diagnose.py` 看按中心的分布，必要时改成按中心留出。
3. **该换 nnU-Net**。手工 2D UNet 的域内上限本来就有限，nnU-Net 2D
   是这一行的标准配方，也不难接——`prepare.py` 的缓存可以直接转成 nnU-Net 格式。

### 对填表的影响

⚠️ **绝对数值不能写进论文**（0.42 太低），但**相对模式是可信的**：
域内 0.42 vs 跨序列 0.10，4 倍差距，方向和 CrossPan 论文一致。
先把表填出来看模式，模型质量后面单独优化。

## 7. 训练速度（4060 Laptop 8 GB 实测）

同一个 2.5D 模型、159 例、5133 张切片，逐项加优化的实测结果：

| 配置 | s/epoch | 300 epoch | 显存峰值 |
|---|---|---|---|
| FP32 + 每张切片在 CPU 做 numpy 增广 | 41.1 | 3.4 h | 0.94 GB |
| \+ 混合精度 bf16 | 39.0 | 3.2 h | 1.99 GB |
| **\+ 整份数据驻留显存 + GPU 增广** | **25.1** | **2.1 h** | **3.24 GB** |
| 同上但 batch 64 | 25.6 | 2.1 h | 5.19 GB |

**结论与教训**：

- 只开 AMP 几乎没用（41.1→39.0，仅 5%），因为 GPU 大部分时间在等 CPU 取数。
  瓶颈是 `num_workers=0` + 每张切片在主线程做 numpy 增广，不是算力。
- 真正的解法是**把整份训练数据搬进显存，增广也放到 GPU 上做**，1.64 倍。
- batch 32→64 不再提速（25.1→25.6），只是多吃 2 GB。**batch 32 是最优点**。
- 显存买到的不是"更大的模型"，是"GPU 不再空转"。

## 9. 患者独立 OOP 主分析与新版运行协议

旧的 OOP `eval` 保留 41 例，适合作为**同患者跨序列分析**。新版 `prepare.py` 还会生成 `eval_patient_disjoint`：排除源模型训练集和验证集中出现过的患者。当前为 26 例。现有 18 组逐病例 Dice 已由 `oop_patient_disjoint.py` 重分析，无需重训；结果和 SHA-256 输入清单在 `outputs/OOP患者独立分析/`。

新版训练入口还支持完整 RNG 播种、嵌套病例抽样、绝对病例数预算，以及保存每格 checkpoint。新协议不要写回旧结果目录；启动新实验前设置隔离路径：

```powershell
$env:EXP_RUNS = 'runs_oop_pd_v2'
$env:EXP_RESULTS = 'results_oop_pd_v2.csv'
$env:EXP_LOG = 'runs_oop_pd_v2/run.log'
$env:EXP_TAG = '_oop_pd_v2'

# 需要重建 patient-level split/物理间距元数据时执行；当前工作区已完成。
.\.venv\Scripts\python.exe 实验DG\code\prepare.py
.\.venv\Scripts\python.exe 实验DG\code\prepare_ct.py

# 新版 patient-disjoint OOP 主矩阵（6 档 × 3 seeds）。训练需时较长。
.\.venv\Scripts\python.exe 实验DG\code\run_grid.py `
  --targets OOP --eval-key eval_patient_disjoint `
  --budgets 0,0.01,0.05,0.1,0.2,1 --seeds 0,1,2 --surface-metrics
```

绝对标注病例数的对照可这样启动（同样会保存逐病例选择清单）：

```powershell
.\.venv\Scripts\python.exe 实验DG\code\run_grid.py `
  --targets CT --label-counts 1,5,10 --seeds 0,1,2 --surface-metrics

# 网格结束后汇总逐病例 HD95 / ASSD，并按患者 bootstrap
.\.venv\Scripts\python.exe 实验DG\code\report_surface_metrics.py
```

`--surface-metrics` 会把逐病例 HD95/ASSD（毫米）另存为 `per_case_metrics.json`；缓存索引需包含 `spacing_zyx`。新 run 的最终权重保存在各自 `model.pt`。旧实验没有微调后权重或边界距离结果，所以它们不能由现有 Dice 表补算。

新协议固定 Python、NumPy、PyTorch CPU/CUDA 随机数，并关闭 cuDNN benchmark；训练设置和病例抽样记录在 `run_metadata.json`。GPU/驱动及部分算子仍可能产生细微非逐位差异，论文应报告多种子变异，不称为跨环境位级完全复现。
